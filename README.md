# Yashasvi Sorapalli's portfolio

Next.js 15 App Router, TypeScript, React, plain CSS, and npm. The book-inspired paper, typography, robot sketchpad, plates, bookmark, and light/dark themes are preserved.

## Develop and verify

```bash
npm install
npm run dev
npm run check # TypeScript, ESLint, production build
npm start     # serve the production build
```

There is no formatter or test runner configured. `next-env.d.ts` is generated by Next.js and excluded from ESLint.

## Routes and content

- `/`: hero with portrait and robot, followed by every featured project card.
- `/about`: author portrait, story, coursework, certificates, and tools.
- `/projects`: all curated projects, a collapsible Hackathon projects section, and a compact GitHub shelf link.
- `/projects/[slug]`: reusable detail template with resources and previous/next navigation.
- `/contact`: existing contact form and LinkedIn option. `/connect` redirects here.
- `/resume`: the public one-page PDF (`public/data/Yashasvi-Sorapalli-Resume.pdf`), embedded on desktop with open and download links.

`content/site.ts` retains existing site copy, project facts, papers, and the original `work` draft, unchanged for later revision. `content/projects.ts` normalizes those existing facts and the two saved repository entries into the shared project model. Cards, detail routes, ordering, and the sitemap use that model. The current collection is curated so route coverage and homepage selection remain consistent; `lib/github.ts` remains available for future live-shelf integration.

Dates are explicitly labeled as repository updates, publication years, or the documented project period. Featured projects sort first, then by year of documented activity/publication, not an asserted completion date. Detail sections without confirmed content are hidden rather than shown as TODOs. ## Privacy and contact delivery

The previous PDF contained personal contact details and has been moved into ignored `.private/`. It is no longer served. Do not commit or deploy that directory. The public replacement in `public/data/` (`site.resumePdf`) was checked for email, phone, address, metadata, links and visual content. Inspect PDF text, metadata, annotations, and every page visually before replacing it. Never programmatically redact a PDF without its source and visual verification.

The form uses the existing `/api/contact` Resend handler. Set `RESEND_API_KEY`, `CONTACT_FROM_EMAIL` (verified sender), and `CONTACT_TO_EMAIL` only on the server. No recipient or mailto fallback is shipped to browsers. With missing settings, the API returns a clear 503 error and the form retains the visitor's message.
